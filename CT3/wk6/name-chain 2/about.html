The Person in the Name

You type a first name. Wikidata, the database behind Wikipedia, is asked about everyone it knows who shares that name: when they were born, where they are from, who they are. Their guesses are handed to a museum, the museum answers with art, and each artwork calls up more art — until twelve images are glued into a mood board of someone who does not exist.

The result is a portrait made entirely of assumptions: the average of everyone with that name who was notable enough to end up on Wikipedia, translated into colours and brushstrokes. The machine does not know you. It only knows the famous strangers who share your name, and it is very confident anyway.

How the chain works

the whole chain. dashed lines carry a guess, pen lines carry a link between artworks.

  1. Trigger. The visitor types a first name and presses Ask the machines. That single submit is the only human action; everything after it is servers talking to servers.
  2. Three questions. The name goes to Wikidata as one SPARQL query that collects up to 400 people whose given name matches: their birth years (the middle one becomes the guessed birth year), their citizenships (the most common becomes the guessed origin) and their recorded sex. Each receipt shows how many people the answer is based on. If Wikidata knows no one with the name, the receipt asks a name-guessing service instead (agify.io, nationalize.io or genderize.io), and if that has no answer either, the letters of the name pick a value and the receipt says so.
  3. Guesses become search terms. The guessed country becomes a search word. The guessed age is turned into a birth year, minus one hundred — the year a great-great-grandparent might have been born — and becomes a date filter (created_after / created_before). Both are sent to The Met's collection API. The Met answers a search with ID numbers only, so every artwork costs one more request; the machine reads them one at a time, with a short pause, because The Met limits how fast one visitor may ask. If The Met doesn't answer, the same question goes to the Cleveland Museum of Art.
  4. Art calls more art. Each artwork that comes back has a title, an artist, a place, a date and a technique. The machine turns one of these into the next request, in one of six ways: a word from its title (“Evening Lake” leads to something else with “lake” in its name), the same artist, the same place (by someone else), the same decade (somewhere else in the world), the same technique, or the same place a hundred years earlier, repeating the rule that turned the guessed birth year into the first search. An artwork never leaves by the door it came in through, and the least-used kind of link is always tried first, so every board mixes all six. When several artworks would fit, the machine picks the one that adds an object type, an artist or a place the board does not have yet. Two seeds become four, four become six. On the board, every link is a pen arrow with its reason scribbled next to it.
  5. The mood board. The twelve artworks are laid out in an editorial grid at different sizes. Between them sit round close-ups cut from the pictures, one artwork title on a torn black strip and a scribbled note of the guesses. Beside the board, the keywords are printed as label-maker tape, and the palette is measured from the pictures themselves: each image is shrunk to 24×24 pixels and its most common colour becomes a paint chip. The three original guesses are printed beside the board as the portrait of an imagined person.

Rules that keep the chain honest

  • Deterministic. Every choice is made by a random generator seeded with the name, so the same name always walks the same path. Change one letter and the whole chain changes.
  • Visible. Every request is printed in a live log, and every artwork is pinned to the board with a thread pointing to the data that caused it.
  • Graceful failure. If a service has no answer, the machine admits it and invents a value from the letters of the name, and labels it as invented.

Responses to the brief

What kind of data is passed around?
It starts as the smallest possible piece of personal data: a first name, a few letters. It is turned into statistics (an age, a nationality probability, a gender probability), then into museum search parameters (a year, a place), then into images and their metadata (titles, artists, places, dates, techniques), then back into search words, and finally into a mood board of images, details, words and colours read from the pixels. At every hop the data changes type — text, number, percentage, date, colour, picture — but each form is derived only from the one before it.
Which services are chained together?
ServiceReceivesReturns
Wikidata query servicea name, inside three SPARQL queriesbirth years, citizenships and recorded sex of everyone with that given name
agify.io, nationalize.io, genderize.io (backup)a namea predicted age, country or gender with a confidence
The Met Collection APIa word, an artist, or a date range; then one ID at a timea list of ID numbers; then each object's metadata and image
Cleveland Museum of Art API (backup)a word, an artist, or a date rangematching open-access artworks with metadata and images
Wikidata was built to describe notable people. The museum APIs were built for scholarship. Neither was meant to be connected to the other, which is where the unexpected outcomes come from.
What does the trigger look like?
A single text field and one button. The trigger is deliberately minimal: the visitor gives away almost nothing, and watches how much the system builds from it. A name can also be passed in the address (?name=Jia), so the chain can be fired from a link.
What is the end result?
A mood board — twelve artworks at different sizes, zoomed-in details, a quoted title, a colour palette and a set of keywords — titled “[Name], as imagined by machines.” Beside it sits the portrait that produced it, with every confidence percentage left visible. Visitors who enter their own name usually find the result oddly fitting and obviously wrong at the same time. That gap is the point: it shows how quickly a fragment of data is inflated into an identity, and how much aesthetic weight a guess can carry once it has passed through enough machines.
Why celebrate the mechanism?
The useful version of this project would be one request: “show me art I might like.” Instead the request takes a detour through demographics, genealogy, language, geography and art-historical cataloguing, roughly thirty requests across five servers. Like a Rube Goldberg machine, the detour is the work; the log and the threads exist so that the detour can be seen.

Credits & notes

Artwork data and images: Cleveland Museum of Art Open Access API and The Met Collection API (public-domain works only). People data: Wikidata (CC0). Backup name predictions: agify.io, nationalize.io, genderize.io, which allow about 100 free lookups a day per network. Every answer is kept in the visitor's browser, so the same name never has to be asked twice.

Built with plain HTML, CSS and JavaScript, no libraries, and hosted on GitHub Pages. Nothing typed into the site is stored by it; the name is only sent to the services listed above.
